# Baseline run 2026-10-19

Agents under test: Claude Sonnet and Claude Haiku, each run as an isolated sub-agent that saw only PROMPT.md and the requirement (no rubric, no traps). 15 cases x 3 runs x 2 agents = 90 answers.

Grader: a separate Claude Opus instance per case, given RUBRIC.md, the case file and the 3 answers. Scores are in each folder's `scores/` as JSON, with a reason for every lost point and every gate.

## Result

| Agent | Cases passed (all 3 runs) | Runs passed | Runs failing G1 (invented requirement) | Runs failing G2 | Avg points /12 |
|---|---|---|---|---|---|
| Claude Sonnet | 5/15 (33%) | 26/45 | 15 | 0 | 10.5 |
| Claude Haiku | 3/15 (20%) | 23/45 | 18 | 3 | 10.6 |

## What the numbers say

- **Points alone would have passed both agents.** Average scores are above 10/12. The gate is what fails them: in about 1 run of 3, the agent states as fact a behaviour the requirement never mentions ("the slot is released", "the user is offered a new link", a relevance rule for search).
- **The same agent invents in one run and not in the next.** That is why a single run proves nothing and the suite needs 3.
- **Weakest criterion for both: C4 expected results** (about 65% of points). Many expected results say "per open question" instead of something checkable.
- **Strongest: negative paths and acceptance coverage** (close to 100%).

## Limits of this baseline (read before quoting the numbers)

- The grader is a model from the same family as the agents. A human spot-check of the G1 verdicts is the next calibration step.
- G1 has borderline calls; the grader logs them as "borderline, not triggered" in the notes so they can be reviewed.
- One run of the suite per agent. Rerun on every model or prompt change and compare.
